### Bounded implementation assumptions
- Preserve existing read input schemas: an explicitly foreign `company_id` is rejected, not silently redirected; actual reads use authenticated grant identity. Missing scope is `ERR_SCOPE_UNAUTHORIZED`, foreign/missing resource or invalid match/company binding is `ERR_RESOURCE_NOT_ALLOWED`. Keep unrelated write allowlist/cooldown error behavior intact.
- Only `get_market_quotes` is the existing public-data exception. Do not change public quote fields, draft/publish rules (#3), contract acceptance (#4), settlement math (#5), or build the external MCP transport/catalog (#9).
- Tenant history attribution is additive and durable; legacy results with unknown ownership fail closed for private history while global engine history remains backward compatible.
- The chosen local owner is configured by the server, never taken from a request body. Bind grants to existing match/company/player relationships on the server. No public registration, external identity provider, or credentials in client build variables.
- Tests use isolated databases/state. Do not rewrite a live database or rotate real credentials during development. A migration must be tested on fresh and legacy populated databases, including rollback/failure.

### Core handoff contracts (implementation, not additional user requirements)
- **T3a owner sessions**: new `backend/src/ownerSessions.ts` exports `OwnerSessions({ ownerId, ownerSecret, sessionTtlMs?, now? })`, `create(providedSecret)` returning `{ token, ownerId, expiresAtUtc }` or undefined, `authenticate(token)` returning only owner metadata or undefined, and `revoke(token): boolean`. Random 32-byte opaque sessions, hash-only in-memory lookup, exact-expiry denial; restart invalidates sessions. Owner secret is configured server-side (the existing server root credential), not client-selected identity. No HTTP/config edits in this independent core unit.
- **T3b grant core**: new `backend/src/grantService.ts` exports `GrantService({ repositories, ownerId, matchId, companyId, allowedLineIds, now? })`, `issue(input)` returning `{ token, grant }` with safe public metadata, `list()`, `get(grantId)`, `revoke(grantId)`, and `resolve(token)` returning the current stored hash-only policy for the gateway. Issue validates scopes/phase/TTL/quotas/allowlist and cannot accept caller-chosen owner/player/match/token. Trusted constructor context limits the owner to the existing server-selected company/match. `resolve` must retain revoked/expired flags for the gateway's exact error codes; it is not standalone authorization.
- Grant storage uses new `StoredMcpGrant` (policy plus `tokenHash`, no raw token), SHA-256 of CSPRNG 32-byte secrets, and safe metadata with neither token nor tokenHash. Migration5 renames legacy `token` to `token_hash`, retires/revokes all legacy grants and scrubs old secrets with unusable digest placeholders while preserving IDs/metadata/audit links. Never apply it to a live database here; document forced reissuance before future deployment. Preserve migration1/schema.sql baseline and existing transaction helpers.
- **T4 parent wiring**: owner-only HTTP administration/session endpoints and server-side gateway resolver use those cores; no public signup or external MCP transport/catalog. Defaults preserve existing production/state/command routes and server-selected company. Parent owns shared HTTP/config/bootstrap/gateway edits, CLI help and end-to-end tests.
